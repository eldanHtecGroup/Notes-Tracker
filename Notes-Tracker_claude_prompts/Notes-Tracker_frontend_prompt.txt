● I've built the frontend in frontend/ with React 19, Vite and plain JavaScript.
  Its 37 unit tests pass and the production build works. I also ran it against
  your backend: notes created through the frontend's dev server reach the API,
  and the backend logs the action (INFO Note created {...}).

  To run it, start the backend, then:
  cd frontend
  npm install
  npm run dev     # http://localhost:5173
  npm test
  The dev server forwards /api requests to localhost:5000. That's also the
  address your backend's .env.example already allows for CORS.

  What it does
  - Add: title (required, max 200 characters) and optional content. The form
    clears after a successful save.
  - View: all notes, most recently changed first. Each one shows "Last modified
    …".
  - Edit: you edit a note in place. Only the fields you changed are sent, so
    saving without changes doesn't update the "last modified" time.
  - Delete: asks you to confirm first.
  - Errors from the backend (bad input, a missing note, server not running)
    appear next to the form or note they relate to. If the notes fail to load,
    there's a "Try again" button.

  How the code is organised
  - src/api/notesApi.js (frontend/src/api/notesApi.js): talks to the backend and
    turns its error responses into a readable message.
  - src/hooks/useNotes.js (frontend/src/hooks/useNotes.js): loads the notes and
    keeps the list up to date after each change.
  - src/components/ (frontend/src/components/): NoteForm (used for both adding
    and editing), NoteList and NoteItem.

  Tests: there's one test file per module under frontend/tests/unit/, the same
  layout as the backend. Add, view, edit and delete are each tested on their own
  and again as complete flows in App.test.jsx
  (frontend/tests/unit/App.test.jsx). The tests replace the backend with a fake,
  so it doesn't need to be running.

  Logging: all logging stays in the backend. Every action in the frontend goes
  through the API, so the backend's existing logs already cover it.
